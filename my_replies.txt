Hiya all, I've figured out how to make godot 2.1.6 works on modern web browser when building a custom export template with help of Scons 2.5.1, Emscripten 1.38.48, and python 2.7.13.
1.
I used the following CMD command on Windows 11:

platform=javascript target=release tools=no disable_3d=yes disable_advanced_gui=yes builtin_openssl=no module_openssl_enabled=no -j1
I had to rip off openssl due to the limited command line length on Windows 11 when linking a static library.
2.
I followed the official guide where it says:

[...] This can be done in the export GUI, using the “Custom Package” option. There’s no need to copy the templates in this case — you can simply reference the resulting files in your Godot source folder, [...].

referenced: https://docs.godotengine.org/en/2.1/development/compiling/compiling_for_web.html.

The export worked on Chrome. Well, almost... The godot.javascript.opt.exe.html ignored the data.pck and just take the following files:
godot.javascript.opt.exe.asm.js
godot.javascript.opt.exe.html.mem
godot.javascript.opt.exe.js

Workaround 1: I took borrow the .html file of the official export template (javascript.release.zip file) and within that file I just went to the lines of code where the asm.js, the html.mem and the .js files where referenced and I just renamed those files. You can check at the following repository: https://minec-c.github.io/export216x64pj1/godotapk2/godot.javascript.opt.exe.html

Workaround 2:
Within the godot.javascript.opt.exe.asm.js file, I replaced the 1th line of code by the 2th line:

_emscripten_get_num_gamepads(){return JSEvents.lastGamepadState.length}
_emscripten_get_num_gamepads(){return 0}
